# v0.3 Schema Freeze Audit

This document defines the final review gate before the `v0.3` RCA contract is declared frozen.

Current status:

```text
v0.3 foundation scope definition:       COMPLETE
v0.3 foundation implementation:         COMPLETE
v0.3 production-hardening follow-ups:   COMPLETE
v0.3 schema freeze candidate:           READY FOR FINAL REVIEW
v0.3 schema freeze audit:               PENDING
v0.3 schema frozen:                     NOT YET
```

The next engineering command is:

```sh
make verify-v0.3-schema-freeze
```

This gate does not add new foundation features. It verifies that the completed tickets compose into a consistent, replayable, backward-compatible, and safe contract.

## Gate 1: CRD Schema Consistency

Verify consistency across:

- `config/crd/bases`
- Helm chart CRDs
- rendered Helm manifests
- rendered Kustomize manifests
- CRD reference documentation

Review focus:

- enum values
- required/optional field semantics
- `omitempty` and nullable behavior
- runtime-enforced versus reserved fields
- status fields:
  - `phase`
  - `outcome`
  - `failure`
  - `degradation`
  - `conditions`
  - `execution`
  - `attempts`
  - `providerResult`
  - `evidenceRefs`
  - `claims`
  - `classification`
  - `payloadRef`

## Gate 2: Legal Status Combinations

Valid combinations:

```text
Pending    + no outcome
Collecting + no outcome
Reasoning  + no outcome
Verifying  + no outcome

Completed + Confirmed
Completed + Inconclusive
Completed + NoIssueFound

Failed + Unknown + failure
```

Invalid combinations:

```text
Failed + Confirmed
Completed + Unknown
Pending + NoIssueFound
Failed without failure
Completed + stale failure
NoIssueFound with incomplete required evidence
```

`Degraded=True` is orthogonal to success/failure. `Completed + Confirmed + Degraded` and `Completed + Inconclusive + Degraded` can both be valid.

## Gate 3: Durable Reconcile Semantics

Review the crash/retry matrix:

```text
provider not called
provider attempt timeout
provider malformed response
provider success before checkpoint persistence
provider result checkpoint persisted
verifier failure
final status patch conflict
controller restart
duplicate reconcile
provider configuration generation changed
evidence bundle changed
```

Required invariants:

```text
same completed logical execution
-> do not call provider again

same execution with incomplete attempt
-> follow retry policy

input, evidence, or provider policy changed
-> new execution
```

FluxAgent does not claim exactly-once provider execution. If the provider succeeds but the controller crashes before checkpoint persistence, duplicate provider requests can still happen unless the provider honors the idempotency key.

## Gate 4: Determinism

The following must remain stable for the same fixture:

- normalized observation ordering
- evidence IDs
- query digest
- content digest
- evidence bundle digest
- execution ID
- finding identity
- incident occurrence identity
- retained truncation subset
- final common RCA structure

Coverage should include:

- map order differences
- backend response order differences
- parallel query completion order differences
- timestamp precision differences
- Prometheus series/sample order
- Loki stream/entry order
- provider-specific response to common RCA normalization

Hosted provider natural-language output itself does not need to be deterministic.

## Gate 5: Evidence And Data Safety

Verify the complete data path:

```text
raw payload
-> size enforcement
-> native result enforcement
-> normalization
-> redaction
-> classification
-> retention decision
-> egress policy
-> provider bundle
-> storage adapter
```

Required checks:

- `allowExternalTransmission=false` sends no hosted provider request
- maximum classification policy blocks transmission
- denied sensitivity tags block transmission
- redaction does not automatically lower classification
- provider result classification is not lower than the transmitted bundle
- `RawSnapshot` remains rejected
- `payloadRef` contains no credentials, signed URL, or filesystem path
- `MetadataOnly` mode still supports complete RCA execution

## Gate 6: Query Safety

Verify the query protection chain:

```text
template policy
-> backend syntax policy
-> network endpoint policy
-> execution count/concurrency budget
-> cumulative duration/bytes
-> backend-native result limits
-> flat-record limits
-> status budget
```

Required checks:

- `QueryPolicyRejected` occurs before network request
- redirects are checked on every hop
- metadata, loopback, link-local, and unspecified addresses are blocked
- private cluster services require explicit allowance
- in-flight queries are canceled where possible after budget rejection
- parallel collection preserves canonical evidence order
- required evidence truncation cannot produce `NoIssueFound`

## Gate 7: Verifier Correctness

Domain-specific evidence requirements:

| Profile | Required Support |
| --- | --- |
| `OOMKilled` | OOMKilled event plus memory metric evidence |
| `CrashLoopBackOff` | matching BackOff/crash-loop event evidence |
| `ImagePullBackOff` | matching image pull event evidence |
| `LatencyRegression` | metric evidence with required completeness |

Verifier invariants:

- verifier can keep or lower confidence
- verifier cannot raise provider confidence
- unsupported or contradictory claims remain visible
- claim evidence links use bounded roles and strengths

## Gate 8: Backward Compatibility

Canonical truth:

```text
InvestigationRequest.status
```

Compatibility projections:

```text
status.summary
status.hypothesis
RiskSignal legacy RCA fields
DirectRiskSignal path
```

Required checks:

- old objects missing new status fields do not panic reconciliation
- v0.2 compatibility fields remain projections
- Helm upgrade does not require CRD deletion
- RiskSignal lineage defaults do not create loops
- unset query policy and data classification defaults are documented

## Foundation Exit Criteria Summary

### A. Contract Stability

- formal workflow/RCA status separation
- durable execution and attempt identity
- canonical digest and finding identity
- bounded status/evidence schema
- canonical claim/evidence semantics

### B. Safety Boundaries

- loop prevention
- datasource SSRF/network safety
- pre-query and post-query budgets
- provider egress and classification controls
- evidence retention and payload reference security

### C. Trustworthiness

- required evidence profiles
- `NoIssueFound` gates
- L1/L2/L3 verification
- evidence-linked claims
- confidence bounding

### D. Evaluation And Operations

- raw-to-normalized fixtures
- provider golden fixtures
- raw-to-final replay
- expanded scenarios
- low-cardinality metrics
- controller-runtime workqueue dashboard

## Not Blocking v0.3 Foundation

These remain outside the foundation exit criteria:

- bounded agentic investigation
- distributed worker pool
- multi-cluster hub/spoke
- approval UI
- remediation execution breadth
- HolmesGPT/OpenSRE provider integrations

Traffic/resource rule packs are implemented as opt-in P1 packaging, but they are not required to freeze the canonical RCA contract.
