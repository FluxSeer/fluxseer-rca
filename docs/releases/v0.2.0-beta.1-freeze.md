## Reproducibility Findings

The release should not be tagged yet.

Blocking gaps:

- Make targets build `fluxagent/operator:latest` and `fluxagent/demo-observability:latest`
- kind gates load local `latest` images instead of immutable release image references
- `config/manager/manager.yaml` uses `fluxagent/operator:latest`
- `examples/kind/manager-demo-patch.yaml` uses `fluxagent/operator:latest`
- `examples/fake-observability/deployment.yaml` uses `fluxagent/demo-observability:latest`
- `charts/kube-ai-sre/values.yaml` uses `image.tag: latest`
- `charts/kube-ai-sre/Chart.yaml` still has `version: 0.1.0` and `appVersion: "0.1.0"`
- built images do not include OCI labels or embedded revision metadata tying the image to the Git commit
- two local rebuilds during the freeze pass produced different image digests
- no upgrade or uninstall smoke test has been run for the beta release

## Freeze Decision

Do not create `v0.2.0-beta.1` yet.

The functional beta gate is green at commit `7ec6de6c4a1c11cf536941e48fd64ff681cd7300`, but release reproducibility is not frozen.

Before tagging:

1. add release image tags or digest-based manifest support
2. add image revision metadata or labels that record the Git commit
3. make kind verification able to run against the intended release image reference
4. align Helm chart version and appVersion with `v0.2.0-beta.1` or document Helm as out of release scope
5. smoke test upgrade and uninstall, or explicitly document both as pending
6. rerun the full beta gate using the release image reference
