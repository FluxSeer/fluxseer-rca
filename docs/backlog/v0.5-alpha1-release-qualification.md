# v0.5.0-alpha.1 Live Cluster Release Qualification

This document is the release gate for `v0.5.0-alpha.1`. It is deliberately
separate from the controller-runtime conformance suites: fake-client PASS is
required evidence, but it is not evidence that Kubernetes API-server watches,
status persistence, rollout timing, or published artifacts work in a real
environment.

The scope is frozen while this gate is open:

> No new feature or detection-domain work before `v0.5.0-alpha.1` release
> qualification completes.

## Evidence tiers

| Tier | Environment | Purpose | Status |
| --- | --- | --- | --- |
| Controller-runtime conformance | fake client plus real reconcilers and adapters | Product contract, CRD projection, evidence provenance, approval sequencing | PASS |
| Live-cluster functional qualification | clean kind cluster with API server and controller watches | Real reconciliation ordering, resourceVersion/generation, status conflicts, rollout and eventual consistency | TODO |
| Published-artifact qualification | clean environment pulling the exact tag from GHCR/OCI | Distribution, version alignment, provenance, and reproducible installation | TODO |

A result from one tier must not be reported as a result from another tier.

## 1. Live-cluster functional qualification

Use a fresh kind cluster and exercise only representative cases. The live
matrix does not need to duplicate every controller-runtime scenario.

### RCA representatives

| Scenario | Required live assertion |
| --- | --- |
| `ServicePortMismatch` | Real Service/workload objects produce the bounded root cause and public report evidence refs. |
| `FailedScheduling` | Real Pending Pod and scheduler event produce the bounded scheduling result. |
| `CrashLoopBackOff` | Real restart state plus application evidence reaches the expected confirmed/inconclusive boundary. |
| `HighHTTPErrorRate` | Prometheus symptom and Loki causal dependency evidence remain linked through the real API-server status path. |

### Remediation representatives

| Scenario | Required live assertion |
| --- | --- |
| `rolloutRestart-effective` | Real approval sequence reaches one Deployment mutation, read-only verification, and `Effective`. |
| `rolloutRestart-ineffective` | Mutation succeeds while the same bad configuration remains; effectiveness is `Ineffective`. |
| `rolloutRestart-inconclusive` | Mutation succeeds while verification is unavailable; execution remains `Succeeded` and effectiveness is `Inconclusive`. |

Every live run must preserve artifacts under a run-specific directory:

```text
internal/summary.json
internal/scenarios/<scenario>/snapshot.json
user-facing/scenarios/<scenario>/report.json
```

The public report must contain only product-visible objects and fields. Harness
assertions, fixture implementation details, and controller debug snapshots are
internal artifacts.

The live gate must explicitly check:

- API-server watch/requeue and status update completion;
- generation and observedGeneration consistency;
- exactly one authorized Deployment mutation;
- execution identity and target UID preservation;
- verification request is `readOnly` and cannot create a remediation chain;
- `Succeeded` execution is not presented as `Effective`;
- no unexpected `RemediationPlan` or `AgentAction` objects.

## 2. Pre-release candidate distribution qualification

The first external distribution run must use an immutable candidate version,
not the final alpha tag. The candidate must identify the exact source commit,
for example:

```text
operator:v0.5.0-alpha.1-rc.35c4295
chart:0.5.0-alpha.1-rc.35c4295
```

The release workflow must be dispatched with `candidate=true` and the exact
40-character `source_ref` commit SHA. Candidate publication must not create or move the final
`v0.5.0-alpha.1` tag. Record the following before clean-room installation:

- source commit;
- operator image digest;
- chart digest and package SHA256;
- chart version and `appVersion`;
- rendered image repository, tag, and RBAC profile.

Candidate qualification has two fresh-cluster runs:

1. default read-only installation;
2. experimental executor installation with one `rolloutRestart` Effective smoke.

Candidate PASS is required before freezing the final release SHA. The
candidate and final artifact reports must remain separate.

## 3. Clean-room distribution qualification

This tier starts from a new cluster and an empty local artifact cache. It must
not use `docker login`, `helm registry login`, a local chart directory, local
image loading, pre-existing CRDs, or a pre-existing FluxSeer namespace.

### Default profile

- anonymously pull the Helm chart from OCI;
- install with remediation and experimental executor disabled;
- verify read-only RCA still works;
- verify the controller ServiceAccount has no workload mutation permission;
- verify no `RemediationPlan` or `AgentAction` is created by RCA.

### Experimental profile

- anonymously pull the exact same chart and operator image tag;
- install with both remediation and experimental executor enabled;
- verify only the allowlisted Deployment `rolloutRestart` mutation is granted;
- run the guarded approval-to-effectiveness path;
- verify verification cannot create a second remediation chain.

## 4. Published-artifact qualification

Run this tier only after the release commit is frozen and the exact tag has
been published:

```text
freeze release commit
→ tag v0.5.0-alpha.1
→ publish operator image and Helm OCI chart
→ anonymous clean-room pull of the exact tag
→ execute live-cluster acceptance
```

The following identity tuple must be recorded and mutually consistent:

| Identity | Required value |
| --- | --- |
| Git tag | `v0.5.0-alpha.1` |
| Git commit | frozen release commit |
| Chart version | `0.5.0-alpha.1` |
| Chart `appVersion` | `v0.5.0-alpha.1` |
| Operator image tag | `v0.5.0-alpha.1` |
| Operator image digest | digest pulled by the clean-room cluster |
| CRD schema | CRDs rendered from the frozen release commit |

The existing release checks remain prerequisites:

```bash
make verify-release-inputs VERSION=v0.5.0-alpha.1
make verify-packaging-consistency VERSION=v0.5.0-alpha.1
make verify-artifact-identity VERSION=v0.5.0-alpha.1 \
  GIT_COMMIT=<frozen-commit> GIT_DIRTY=false BUILD_DATE=<release-build-date> \
  OPERATOR_IMAGE_REF=ghcr.io/fluxseer/fluxseer-rca/operator:v0.5.0-alpha.1 \
  DEMO_IMAGE_REF=ghcr.io/fluxseer/fluxseer-rca/demo-observability:v0.5.0-alpha.1
make verify-release-cleanup VERSION=v0.5.0-alpha.1
```

The release is not declared until all three tiers are green and the GHCR
package visibility plus anonymous OCI pull have been verified before the final
clean-room run.
