# FluxAgent v0.2.0-alpha.2

Release date: 2026-07-23

## Status

`v0.2.0-alpha.2` is best described as:

```text
v0.2 alpha+ / early v0.3 alpha
```

It is a runnable read-only RCA platform with datasource contracts, degraded-state visibility, hosted provider hardening, and an early CRD-first ad-hoc investigation workflow.

This is not a production-grade autonomous remediation release.

## Highlights

- `RiskRule`, `DataSource`, `ModelProvider`, and `InvestigationRequest` CRDs are wired into the controller runtime path.
- `RiskRule -> RiskSignal` supports read-only evidence collection, RCA persistence, and webhook notification.
- `InvestigationRequest` supports ad-hoc read-only RCA, explicit `queries[]`, and optional promotion into `RiskSignal`.
- `fluxagent investigate` creates `InvestigationRequest` objects and can wait for terminal status.
- Datasource references and query capabilities surface degraded status instead of crashing reconciliation.
- Evidence is redacted before provider-bound reasoning.
- Hosted OpenAI, Gemini, and Claude providers share timeout, retry, and HTTP status handling.
- `ModelProvider.spec.fallbackProviderRef` supports provider failover for supported provider and secret failures.
- `RiskSignal` and `InvestigationRequest` support TTL cleanup behavior.

## Verified Gates

The release checkpoint was verified with:

```sh
GOWORK=off go test ./...
kubectl kustomize config/default >/tmp/fluxagent-config-default.yaml
kubectl kustomize examples/kind >/tmp/fluxagent-kind-example.yaml
make verify-e2e-kind
make verify-investigation-kind
```

The kind gates covered:

- read-only `RiskRule -> RiskSignal`
- webhook notification
- missing datasource degradation
- datasource capability mismatch degradation
- hosted provider `ProviderAuthFailed` degradation
- `InvestigationRequest -> RCA`
- optional `InvestigationRequest -> RiskSignal` promotion
- investigation degradation for missing datasource, capability mismatch, missing provider, provider auth failure, and provider rate limiting
- kind cleanup for `fluxagent-demo`

## Known Gaps

- Full `v0.2` definition of done is not closed.
- Adapter auth, retry, and backoff behavior is not production-hardened across all integrations.
- Hosted provider response governance still needs more hardening.
- GitOps PR backends and richer approval UX are not complete.
- Remediation remains guarded and secondary, not the default product path.
- OpenTelemetry and CloudWatch remain scaffold-level integrations.
- Bedrock remains scaffolded compared with the currently wired hosted provider paths.

## Recommended Next Work

1. Keep `make verify-v0.2-alpha`, `make verify-e2e-kind`, and `make verify-investigation-kind` green.
2. Harden provider auth, retry, timeout, and response-governance behavior.
3. Expand provider contract coverage beyond heuristic plus the currently wired hosted paths.
4. Re-check release assumptions before calling the project `v0.2` complete or cutting a broader `v0.3` alpha.
