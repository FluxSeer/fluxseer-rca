# FluxSeer RCA v0.3.0-beta.3

Status: candidate notes for beta hardening.

## Focus

`v0.3.0-beta.3` is planned as an additive hardening release on top of the `v0.3.0-beta.2` RCA control-plane direction.

The release focuses on making canonical RCA state easier to consume and audit:

- bounded provider egress attempt history
- provider fallback egress policy traceability
- query retention controls
- AgentAction status-first remediation projections
- evidence store backend contract clarity
- ecosystem integration documentation

## API And Compatibility

This candidate includes additive `v1alpha1` status/spec hardening. It should be treated as a beta.3 schema candidate, not as an unchanged beta.2 frozen contract.

Notable additive fields:

- `InvestigationRequest.spec.queryRetention`
- `InvestigationRequest.status.execution.egressAttempts[]`
- `AgentAction.status.approval`
- `AgentAction.status.dryRunResult`
- `AgentAction.status.execution`
- `AgentAction.status.effectiveness`

Compatibility fields remain available where required:

- `InvestigationRequest.status.execution.egressAudit`
- `AgentAction.spec.approvedBy`
- `AgentAction.spec.dryRunResult`

## Verification

Use the beta hardening gate for this candidate:

```sh
make verify-v0.3-beta-hardening
```

This gate validates Go tests, CRD source/chart synchronization, Kustomize rendering, Helm lint/render, rule pack rendering, RBAC profiles, and schema smoke checks.

It intentionally does not compare CRD/API files against the `v0.3.0-beta.1` frozen baseline because beta.3 includes expected additive schema hardening.
