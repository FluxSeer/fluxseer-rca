# FluxAgent v0.2.0-beta.1

Status: draft, not tagged

Target date: pending release gate completion

## Status

`v0.2.0-beta.1` should be described as:

```text
v0.2 read-only RCA beta
```

It is intended to represent a runnable read-only RCA platform with datasource contracts, degraded-state visibility, hosted provider validation, and a CRD-first ad-hoc investigation workflow.

This is not a production-grade autonomous remediation release.

## Highlights

- `RiskRule`, `DataSource`, `ModelProvider`, and `InvestigationRequest` CRDs are wired into the controller runtime path.
- `RiskRule -> RiskSignal` supports read-only evidence collection, RCA persistence, webhook notification, and typed degradation.
- `InvestigationRequest` supports ad-hoc read-only RCA, explicit `queries[]`, and optional promotion into `RiskSignal`.
- `fluxagent investigate` creates `InvestigationRequest` objects and can wait for terminal status.
- Datasource references and query capabilities surface degraded status instead of crashing reconciliation.
- Prometheus and Loki datasource query paths share retry, timeout, HTTP status, and payload error classification.
- Datasource auth, rate-limit, unavailable, invalid-request, and invalid-response failures map to stable status reasons.
- Background detection can preserve partial evidence when an optional datasource query fails.
- Evidence is redacted before provider-bound reasoning.
- Hosted OpenAI, Gemini, and Claude providers share timeout, retry, and HTTP status handling.
- Structured provider responses are validated before RCA fields are persisted.
- `ModelProvider.spec.fallbackProviderRef` supports provider failover for supported provider and secret failures.
- `RiskSignal` and `InvestigationRequest` support TTL cleanup behavior.

## Pending Release Gate

The beta tag should not be cut until the following commands pass on a clean branch synchronized with `origin/main`:

```sh
make verify-v0.2-alpha
make verify-e2e-kind
make verify-investigation-kind
kind get clusters
git status --short --branch
```

Expected coverage:

- `make verify-v0.2-alpha` covers `go test ./...`, `kubectl kustomize config/default`, and `kubectl kustomize examples/kind`.
- `make verify-e2e-kind` covers read-only `RiskRule -> RiskSignal`, webhook notification, datasource degradation, hosted provider auth failure degradation, and kind cleanup.
- `make verify-investigation-kind` covers `InvestigationRequest -> RCA`, optional `RiskSignal` promotion, investigation degradation paths, and kind cleanup.

## Known Gaps

- Autonomous remediation is not the default product path.
- Remediation remains guarded and secondary through `RemediationPlan` and `AgentAction`.
- GitOps PR backends and richer approval UX are not production-ready.
- OpenTelemetry and CloudWatch remain scaffold-level datasource integrations.
- Bedrock remains scaffolded compared with the currently wired hosted provider paths.
- Multi-cluster policy hardening is not complete.
- Provider coverage is not vendor-complete beyond the currently wired and tested behavior.
